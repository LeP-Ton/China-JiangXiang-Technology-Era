# 企业标识与拟真酒瓶联动

## 背景与目标

- 会话-18 起，用户指出企业标题接近纯文字、选择的标识未更新左上角、品牌名未同步到创建页酒瓶，以及产品页酒瓶过于粗糙。
- 在同一个 `main` 分支完成视觉更新，沿用现有 GitHub Pages 发布流程。
- 形成统一企业形象：企业门楣 → 企业卡片 → 创建页酒瓶 → 产品页酒瓶。

## 约束与原则

- 使用 React / SVG / CSS，品牌、名称、标识可实时渲染。
- 保留存档中的 `company.logo` 字符键和图片数据，不改变存档结构。
- 酒瓶复用同一组件，避免创建页与产品页的精细度和排字再次分离。
- 不改变生产、价格、配方、财务或其他模拟规则；既有存档直接使用新展示。

## 关键实现与风险

- 不把动态品牌文字做进静态图片，输入后的反馈由受控 React 状态直接驱动。
- 预设标识保留旧键，旧档中的标识会自动获得新矢量外观。
- 上传标识须在普通 HTML 图片和 SVG `image` 中一致显示。
- 长品牌分列必须限制总宽度；手机创建页需保留瓶底，产品页展示区不能被通用面板内边距挤压。
- 多酒瓶的渐变 ID 必须唯一，雅致与典藏同时出现时不能互相引用材质。

## 测试用例

### TC-001 标识实时同步

- 类型：浏览器功能测试；优先级：高。
- 操作：创建页依次选远山、酿印、金穗、醴泉，输入“沧海酒业”，观察门楣和瓶身。
- 预期：三处同步，不出现固定“酱”或旧标识。
- 结果：通过，四个键分别为“山 / 酱 / 谷 / 醴”。

### TC-002 创建与读档

- 类型：浏览器功能测试；优先级：高。
- 操作：选择金穗创建“沧海酒业”，进入产品页并刷新。
- 预期：门楣、企业卡片、瓶身仍是同一徽记，品牌为“沧海”。
- 结果：通过，三个图形一致；旧“知微酒业”档案也可直接显示。

### TC-003 上传标识

- 类型：浏览器功能测试；优先级：高。
- 操作：在创建页上传小于 200 KB 的测试 PNG。
- 预期：表单、门楣及瓶身使用同一图片。
- 结果：通过，HTML 图片与 SVG 图片地址一致。

### TC-004 品牌与长名称

- 类型：浏览器视觉测试；优先级：高。
- 操作：输入“沧海”，再输入 30 字品牌及企业名。
- 预期：即时更新，文字完整，长品牌缩字分列，不覆盖酒标边界。
- 结果：通过，30 个字符全部保留，字号自动调整至 14；手机创建页没有横向溢出。

### TC-005 包装与多实例

- 类型：浏览器视觉测试；优先级：中。
- 操作：实际创建并勾调典藏产品，与雅致产品同时展示。
- 预期：相同精细瓶型，白釉与深翠金标分开显示，每瓶有独立渐变与裁剪 ID。
- 结果：通过，两个产品均显示企业金穗徽记，无串色和运行异常。

### TC-006 移动端

- 类型：390px 宽度视觉测试；优先级：中。
- 操作：创建页长名称、抽屉导航与产品页。
- 预期：无页面横向溢出、酒瓶完整、标题与品牌可见。
- 结果：通过。针对预览发现的瓶底裁剪和通用面板内边距作了修正。
