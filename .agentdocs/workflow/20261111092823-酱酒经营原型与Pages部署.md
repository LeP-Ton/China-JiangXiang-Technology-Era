# 酱酒经营原型与 GitHub Pages 部署

## 背景与目标

- 对应会话-1 开始的首轮开发，后续用户追加发布至 GitHub Pages。
- 空项目、`main`、无历史提交与远程仓库。实现研发 → 配方 → 生产 → 陈酿 → 勾调 → 销售 → 回款 → 再投资的可玩闭环。
- 企业管理软件式界面，全部品牌、企业和事件均为原创虚构设定。

## 约束与决策

- TypeScript / React / Vite / CSS / Recharts；纯规则与 UI 分离，不接外部模型 API。
- 金额万元，基酒吨，成品瓶；1 吨折算 2,000 瓶，另扣灌装损耗。
- 每月 5 次管理行动，调价和事件选择不耗行动。操作原子化，失败不扣款、不推进随机状态。
- 研发、盲品、市场与风险使用随存档保存的固定种子序列。
- 用户指定 Pages 后以其为正式目标；此前 Sites 草稿未发布，配置仅在本地保留并忽略提交。

## 关键实现

- `performAction` 克隆状态执行命令，验证失败返回原状态。
- 月结：研发 → 储存 → 生产 → 行业周期 → 销售 / 回款 → 风险 → 财务 → 月报 → 重建当期账本 → 新月事件。
- 发货确认收入与成本，赊销收 40%，余款两月后到期，依经销商现金和健康度回收。
- 经销终端销售不重复计入企业营收；库存覆盖、倒挂、现金和坏账共同约束扩张。
- 原料加工先形成库存，勾调按实际耗用转成品成本；折旧不重复扣现金。
- 有限陈化曲线，长期削弱果香；挥发减量但不虚增成本价值。
- 实验保留预测、实测与工艺快照，按工艺距离加权残差，校准幅度设上限。
- 每类事件每局一次，前置可查 `events.ts`；夸大宣传另有持续月度风险抽样。
- 存档带版本、校验和、结构与数值验证；自动档、三槽手动档和文件备份相互配合。

## 测试用例

### TC-001 完整经营闭环

- 类型：回归 + 浏览器；优先级：高。
- 操作：创建、盲品、研发、生产 3 吨、选 12 月基酒灌装 2,000 瓶、赊销 1,000 瓶并月结。
- 预期：原料和基酒减少、成品增加再出库；收入、现金、应收独立。
- 状态：通过。确认收入 11.09 万，实收 4.44 万，应收 6.65 万。

### TC-002 跨月财务

- 类型：回归 + 浏览器；优先级：高。
- 操作：连续推进检查清零与历史。
- 预期：前月收入、研发、费用不重复结转。
- 状态：通过。独立月收入 6.90 万和 6.54 万。

### TC-003 科研与部署

- 类型：回归；优先级：高。
- 操作：四阶段投入、等待、失败重试和部署。
- 预期：人员和前置约束有效，失败不退经费，部署改善生产。
- 状态：通过，覆盖节粮、周期、出酒率与风味。

### TC-004 渠道压货

- 类型：回归；优先级：高。
- 操作：单一渠道过量出货并月结。
- 预期：健康下降、倒挂、后续拒收。
- 状态：通过。

### TC-005 存档复现

- 类型：回归 + 浏览器；优先级：高。
- 操作：第 3 月保存，推进到 4 月，读档刷新；文件导出、推进后再导入。
- 预期：企业、月份、现金、批次和随机状态恢复，损坏档拒绝。
- 状态：通过，恢复自定义“知微酒业”第 3 月、306.15 万现金。

### TC-006 长期与异常

- 类型：回归；优先级：高。
- 操作：补原料、投产、勾调、适量补货与研发持续 72 月；测试负数、NaN、过量、错误批次和负现金清算。
- 预期：超标准周期可继续，档案始终有效，非法输入不污染状态。
- 状态：22 项全部通过，含固定种子、失败、复购和融资自救。

### TC-007 浏览器与视觉

- 类型：桌面 / 移动宽度验证；优先级：中。
- 操作：全部模块、控制台、390px 导航和布局。
- 状态：无当前浏览器运行错误，无页面横向溢出；其他真机和浏览器未覆盖。

## 关键风险与后续

- 月结调用顺序、成本结转与随机消耗顺序影响存档复现，修改时须跑回归。
- 上市、并购、独立竞品和更多合同留在 TODO.md，不展示无实际功能的按钮。
- 本轮是完整可玩原型，不是实际酒业财务或工艺工具。
- 后续修改优先读本文件，再执行 `npm test`、`npm run build`，必要时复核浏览器账目。
